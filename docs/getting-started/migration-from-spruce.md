# Migration from Spruce

Graft is a drop-in replacement for Spruce with additional features. This guide helps you migrate smoothly.

## Compatibility

Graft aims to run any Spruce configuration unchanged:

- Spruce's operators behave the same way
- Spruce's commands (`merge`, `diff`, `json`, `fan`, `vaultinfo`) and every
  one of its flags are supported under the same names
- Merge semantics — deep map merge, the array-merge markers, cherry-picking,
  and pruning — are preserved

The differences that remain are catalogued in
[Known Gaps](../spruce/known-gaps.md); none of them affect existing
configurations.

## Quick Migration

### Step 1: Install Graft

```sh
go install github.com/fivetwenty-io/graft/cmd/graft@latest
```

### Step 2: Alias or Replace

Option A - Create an alias:

```sh
alias spruce=graft
```

Option B - Replace the binary:

```sh
sudo mv $(which spruce) $(which spruce).bak
sudo ln -s $(which graft) /usr/local/bin/spruce
```

### Step 3: Test

Run your existing scripts - they should work without modification:

```sh
spruce merge base.yml overlay.yml  # Actually runs graft
```

## What's New in Graft

Everything Spruce does still works. On top of it, Graft adds the following.

### Control Flow

Spruce has no conditionals or loops; a template that needs them has to be
generated by something else first. Graft expands `if`, `for`, `while`, and
`case` blocks into plain YAML before the document is parsed:

```yaml
# app.yml
environment: production
cloud_provider: aws
services:
  - name: api
    port: 8080
  - name: web
    port: 80

(( if environment == "production" ))
replicas: 5
(( else ))
replicas: 1
(( fi ))

endpoints:
(( for service in grab services ))
  - name: (( grab service.name ))
    port: (( grab service.port ))
(( done ))

(( case grab cloud_provider ))
(( when "aws" ))
storage_class: gp3
(( when "gcp" ))
storage_class: pd-ssd
(( default ))
storage_class: standard
(( esac ))
```

**Output** (`graft merge --prune services app.yml`):

```yaml
cloud_provider: aws
endpoints:
- name: api
  port: 8080
- name: web
  port: 80
environment: production
replicas: 5
storage_class: gp3
```

See [Control Flow](../user-guide/operators/control-flow.md) for the full
rules, including the `while` iteration cap and the 64-level nesting bound.

### Infix Expressions

Spruce evaluates only whole operator calls, so `(( a + b ))` is read as a
call to an operator named `a`. Graft evaluates arithmetic, comparison,
boolean, and ternary expressions directly:

```yaml
a: 1
b: 2
large: true

sum: (( a + b ))                       # 3
in_range: (( a >= 1 && a <= 10 ))      # true
size: '(( large ? "8Gi" : "2Gi" ))'    # 8Gi
```

An expression containing a ternary has to be quoted, because YAML reads the
bare `: ` as a mapping key.

### field=value Predicates

Spruce resolves a list entry only by index. Graft selects one by matching a
field, in either the dotted or the bracketed spelling:

```yaml
servers:
  - name: primary
    host: db1.example.com
  - name: replica
    host: db2.example.com

primary_host: (( grab servers.name=primary.host ))
replica_host: (( grab servers[name=replica].host ))
```

The same predicates work in `--cherry-pick` and `--prune`, where only the
**dotted** spelling is accepted:

```sh
graft merge --cherry-pick 'servers.name=primary' config.yml
graft merge --prune 'servers.name=replica' config.yml
```

### type, flatten, and uniq

```yaml
sample:
  count: 3
  list: [1, 2]

nested:
  - [1, 2]
  - [3, [4, 5]]

with_dupes: [zebra, apple, zebra, mango, apple]

kind: (( type sample.count ))     # int
flat: (( flatten nested ))        # [1, 2, 3, 4, 5]
deduped: (( uniq with_dupes ))    # [zebra, apple, mango]
```

`type` names its argument's type as a string — one of `string`, `int`,
`float`, `bool`, `array`, `map`, or `null`. `flatten` is fully recursive and
takes no depth argument. `uniq` keeps the first occurrence of each element
and preserves input order; it never sorts.

### Unquoted calc and Named Variables

Spruce's `calc` takes a quoted expression of literals only. Graft accepts the
expression unquoted, and resolves bare names against the document — first as
a sibling of the key being computed, then from the document root:

```yaml
base: 10
rate: 3
total: (( calc (base + rate) * 2 ))    # 26
doubled: (( calc "base * 2" ))         # 20
```

The unquoted form covers infix arithmetic and parenthesised grouping only;
function calls such as `max(a, b)` need the quoted form.

### NATS as a Secrets Backend

Spruce supports Vault, AWS Parameter Store, and AWS Secrets Manager. Graft
adds NATS JetStream KV and Object stores:

```yaml
config: (( nats "kv:config/settings" ))
template: (( nats "obj:assets/template.yml" ))
```

### Named Backend Targets

A single lookup can be routed at a named backend configuration by writing
`@<target>` on the operator name:

```yaml
prod_password: (( vault@production "secret/db:password" ))
stg_password: (( vault@staging "secret/db:password" ))
prod_host: (( awsparam@prod "/app/config" ))
```

Each target is configured through its own environment variables —
`VAULT_<TARGET>_ADDR` and `VAULT_<TARGET>_TOKEN`, `AWS_<TARGET>_REGION` and
friends, `NATS_<TARGET>_URL`.

### Embeddable Go Library

```go
import "github.com/fivetwenty-io/graft/pkg/graft"

engine, _ := graft.NewEngine()
base, _ := engine.ParseFile("base.yml")
overlay, _ := engine.ParseFile("overlay.yml")

result, _ := engine.Merge(ctx, base, overlay).Execute()
yaml, _ := result.ToYAML()
```

## Feature Comparison

| Feature | Spruce | Graft |
|---------|--------|-------|
| Basic merge | Yes | Yes |
| `grab`, `concat`, `join`, `split`, `stringify`, `keys` | Yes | Yes |
| Array merge markers (`append`, `prepend`, `merge`, ...) | Yes | Yes |
| `vault`, `vault-try` | Yes | Yes |
| `awsparam`, `awssecret` | Yes | Yes |
| `calc` with a quoted expression | Yes | Yes |
| `\|\|` fallback | Yes | Yes |
| go-patch support | Yes | Yes |
| `raw_env` | Yes | Yes |
| Infix arithmetic — `(( a + b ))` | No | Yes |
| Comparison operators — `==`, `!=`, `<`, `>`, `<=`, `>=` | No | Yes |
| Boolean operators — `&&`, `!` | No | Yes |
| Ternary — `? :` | No | Yes |
| `calc` with named variables and unquoted expressions | No | Yes |
| `field=value` predicates | No | Yes |
| `type`, `flatten`, `uniq` | No | Yes |
| if/elif/else/fi | No | Yes |
| for/done, while/done | No | Yes |
| case/when/default/esac | No | Yes |
| `nats` | No | Yes |
| Named backend targets — `(( vault@prod ... ))` | No | Yes |

Where the table says Spruce has an operator, it evaluates the same way in
Graft. Where it says Spruce does not, Spruce either reports
`(( <name> )) operator not defined` or leaves the expression in the output
as literal text.

## Flag Comparison

Every Spruce flag works in Graft:

| Flag | Spruce | Graft |
|------|--------|-------|
| `--skip-eval` | Yes | Yes |
| `--prune` | Yes | Yes |
| `--cherry-pick` | Yes | Yes |
| `--go-patch` | Yes | Yes |
| `--multi-doc` | Yes | Yes |
| `--fallback-append` | Yes | Yes |

Graft adds:

| Flag | Description |
|------|-------------|
| `--max-loop-iterations` | Raise or lower the `(( while ))` iteration cap (default 1000) |
| `--dataflow-order` | Order of operations in dataflow output: `alphabetical` or `insertion` |
| `--config` | Path to a YAML configuration file |
| `--color` | Force colorized output on (default: `auto`) |
| `--no-color` | Force colorized output off, overriding `--color` |

## Migration Tips

### 1. Test Your Configurations

Run Graft on your existing configurations and compare output:

```sh
spruce merge base.yml overlay.yml > spruce-output.yml
graft merge base.yml overlay.yml > graft-output.yml
diff spruce-output.yml graft-output.yml
```

### 2. Update CI/CD Scripts

If you're using Spruce in CI/CD, you can:

- Keep using `spruce` command (with alias)
- Update to `graft` command (recommended)

### 3. Take Advantage of New Features

Once migrated, consider using:

- Control flow for cleaner configurations
- `field=value` predicates instead of list indexes
- Infix expressions instead of nested `calc` calls
- Library embedding for custom tools

### 4. Update Documentation

If you have internal documentation referencing Spruce:

- All operator syntax remains the same
- All merge semantics remain the same
- Only new features need documentation updates

## Troubleshooting

### "Unexpected token" errors

Graft parses expressions rather than treating them as a name plus a list of
words, so a few shapes Spruce tolerated now report an error:

1. Check for unbalanced parentheses in operators

2. Ensure strings are properly quoted

3. A whole expression cannot be wrapped in parentheses —
   `(( (join "," (grab a)) ))` fails; write `(( join "," (grab a) ))`

4. `))` is the expression terminator, so two closing parentheses cannot sit
   next to each other inside one — write
   `(( base64 (concat "x-" (grab name) ) ))`, with a space

### "operator not defined" errors after switching back

Because `type`, `flatten`, and `uniq` are registered in Graft and not in
Spruce, a template that emitted `(( type ... ))` as literal text for a later
pass now evaluates it instead. Wrap it in `(( defer ))` to keep the old
behavior.

### "mapping value is not allowed in this context"

This is YAML, not Graft. An expression containing `: ` — a ternary, or a
string literal with a colon and a space in it — has to be quoted:

```yaml
size: '(( large ? "8Gi" : "2Gi" ))'
```

Expressions also have to stay on one line; a plain YAML scalar cannot span
lines.

### Output ordering

Graft sorts map keys at every level with a port of Spruce's own
comparator — numeric-looking keys first (numerically), then string keys
with digit runs compared numerically (`item2` before `item10`) — so
output key order is directly comparable between the two. See
[YAML formatting differences](../spruce/yaml-formatting.md#known-differences)
for the residual key-label differences on bare numeric keys.

### Environment variables

Graft uses the same environment variables as Spruce:

- `VAULT_ADDR`, `VAULT_TOKEN`, `VAULT_NAMESPACE`, `VAULT_SKIP_VERIFY`
- `AWS_REGION`, `AWS_PROFILE`, `AWS_ROLE`
- `REDACT`

Plus variables for the NATS backend and for Graft's own settings:

- `NATS_URL`, `NATS_TLS`, `NATS_TIMEOUT`, and the other `NATS_*` options
- `GRAFT_MAX_LOOP_ITERATIONS`, `GRAFT_FILE_BASE_PATH`, and the other
  `GRAFT_*` options

Named targets add a per-target form of the backend variables:
`VAULT_<TARGET>_ADDR`, `VAULT_<TARGET>_TOKEN`, `AWS_<TARGET>_REGION`,
`NATS_<TARGET>_URL`.
